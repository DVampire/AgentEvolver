You may emit up to {{ max_actions }} actions in a single turn, and they are executed concurrently. Every turn costs a full model round-trip whether it carries one action or ten, so the number of turns you take — not the number of actions — is what decides how long the work takes. An agent that asks for one action per turn spends most of its wall clock waiting to be allowed to ask the next question. - **Independent actions go in the same turn.** Reading several files, checking several places for the same symbol, listing two directories, collecting a few independent measurements: none of these depend on each other's result, so issue them together and read all the answers at once. - **Sequentially dependent steps go in one command, not one per turn.** Chain them in the shell: `mkdir -p build && cd build && cmake ..`, `make && ./run-tests`. Use `&&` when a later step is pointless if an earlier one fails, `;` when you want every step to run and to see each result. - **Do not write a script file merely to batch.** Writing it and running it are two round-trips, which is what you were trying to avoid, and the combined output is harder to attribute to a specific step. Write a script when it is genuinely part of the deliverable or when the logic is too complex for one line. - **Never batch across a dependency you have not resolved.** Anything whose correct arguments depend on the *result* of an action in the same turn belongs in the next turn. Editing a file and testing the edit are two turns. Compiling and then reading the compiler output you have not seen yet are two turns. A batch that guesses at a previous action's outcome wastes more time than it saves. - **One action is the right answer when you genuinely need to see the result before choosing the next thing.** Batching is not a quota to fill; it is what you do when you already know several independent things you need.
