02 / TWO OUTCOMES

Better products.
More capable agents.

A product improvement changes what people experience. A system improvement preserves a reusable way to do the work. Each needs its own evidence.

PRODUCT LOOP

Experience it before judging it.

Use the actual browser or game controls. Inspect rendered images, finish a real journey, and look for a more useful, expressive or personal interaction. Build the idea and repeat the journey.

Build → Experience → Critique → Improve
CAPABILITY LOOP

Keep the method that earns its place.

A creative idea, a repeated operation or a local check can reveal a better method. Inspect existing capabilities, preserve a baseline, and test a separate candidate against comparison and reuse cases.

Observe → Compare → Adopt → Reuse

Self-evaluation is recorded judgment, supported by real calls. Registration alone is not verified improvement; an unsuccessful candidate is rolled back or unloaded.

06 / VISIBLE EVIDENCE

Follow the work.
Experience the result.

The workbench, run monitor and deployed products are connected through the Gateway. Inspect what happened, what it cost and which artifact was actually published.

↗

A workspace for the whole task

Chat, Canvas, Code and Science share project resources. Browse capabilities, edit files and inspect task activity.

 ↗

Runs, requests and cost

The shared launcher registers runs on gateway port 9876. Trace-backed views expose steps, errors, tokens, cache and compaction activity.

 ↗

Live products, with versions

Deploy publishes websites and Godot playtests through stable site URLs. Run pages link the release and its archived versions.

Trajectories for research

Trajectory hooks capture model context, actions, observations and usage. Evaluator rewards can be backfilled for SFT / RL export. Training execution and serving a trained model are separate integrations.

Controls with explicit boundaries

Permission checks, optional plan approval, shared budgets and backend isolation govern execution. Admission validates an extension’s structure; it does not certify its functional quality.

07 / GET STARTED

Bring a task.
Choose your capabilities.

Install the framework, configure your model provider, then launch a task. The example commands are for your local checkout.

  1. Install the framework

    git clone https://github.com/DVampire/AgentEvolver.git
cd AgentEvolver
bash scripts/install.sh
conda activate agentos

  2. Configure a model route

    Set LLM_HUB_API_BASE and LLM_HUB_API_KEY in your local .env for these examples. Other providers are supported through configuration.

Full installation guide →
RUN A TASK
python examples/run_meta_agent.py \
  --task "Build a useful tool and verify it." \
  --cfg-options model_name=llm_hub/gpt-6-astra

A configurable orchestrator with specialist agents. Review the selected config and permissions before a long run.

python examples/run_website_evolution_demo.py \
  --scenario-dir examples/tasks/website_evolution/commonspace_forum \
  --model llm_hub/gpt-6-astra

Requires the browser dependencies and deployment setup described in the website demo guide.

python examples/run_game_development_demo.py \
  --task-dir examples/tasks/game_development/tidebound_echoes \
  --model llm_hub/gpt-6-astra

Build the Godot Docker images first. The default milestone is a vertical slice; --milestone campaign requests the campaign. See the game setup guide.
