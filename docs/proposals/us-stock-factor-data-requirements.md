# 美股因子挖掘：历史数据需求与来源

更新：2026-09-11。用户已明确研究市场为**美股**。当前任务是整理因子与因子策略挖掘所需的历史数据；仅更新文档与进行公开资料核验，未购买商业数据、建设全量数据集或修改研究代码，实盘接入后置。

关联：[总体方案](factor-strategy-mining-agent.md)、[此前的 BTC 数据方案](factor-strategy-data-sources.md)。本文沿用此前的单资产范围：可以只交易一只股票，同时使用大盘、行业和公司信息构建输入。日频/周频是建议起点，尚未确定具体股票或最终决策频率；不会默认改成全市场选股。

**NVIDIA 专项核查见 [NVDA 历史数据 API、覆盖年限与粒度对照表](nvda-historical-data-api-matrix.md)**，包含多个官方来源、套餐边界、SEC 公开 API 实测和未确认的数据缺口。

## 1. 先回答需要哪些数据

**建议首批准备：原始日线量价、公司行动、证券与交易状态、历史股本、当时可见的财务报表、财报及重要公告、大盘与行业参照，以及回测成本信息。逐笔成交和全量新闻按研究假设再增加。**

优先级由本项目的研究需要确定，不代表所有股票策略必须依赖同一套数据。只研究量价信号时可以先不接财务；若要挖估值、盈利质量、成长等基本面因子，财务与历史股本应进入首批。

| 数据类别 | 应取得的历史内容 | 可以研究什么 | 建议优先级 |
| --- | --- | --- | --- |
| **原始 OHLCV 与成交活跃度** | 未复权 OHLC、成交股数、可得成交额/VWAP/笔数；交易时段和数据覆盖口径 | 动量、反转、波动、跳空、量价关系、流动性代理 | **基础必需**；先日线，日内研究再补分钟线 |
| **公司行动与收益调整** | 拆股/合股、现金与股票分红、分拆、并购换股/现金对价、证券终止事件；公告及生效时间、价格/股数调整规则 | 正确计算收益、股息率、公司行动事件；避免把拆股识别为暴跌 | **基础必需**；不能只留一列 adjusted close |
| **证券身份与交易状态** | 稳定证券 ID、发行人 ID、历史 ticker、股份类别、上市/退市、交易所、停牌、交易日历 | 连续追踪同一证券、过滤不可交易区间；扩展选股时恢复历史股票池 | **基础必需** |
| **历史股本与流通信息** | 在外流通股数、可得自由流通股数、股份类别、变动与披露时间；市值计算口径 | 换手率、稀释/回购、估值分母、流通规模 | **首批建议**；估值和换手研究必需 |
| **财务三表及其历史版本** | 利润表、资产负债表、现金流量表；报告期间、首次公开时间、修订版本、币种及会计口径 | 盈利质量、成长、估值、杠杆、现金流、投资与应计项目 | **首批建议**；基本面因子必需 |
| **业绩披露和重要公告** | 业绩发布、财报提交、公司指引、回购、增发、并购、管理层重大变动等原文与事件时间 | 业绩变化、公告后反应、事件窗口与风险条件 | **首批保留财报/业绩事件**；其他事件按假设扩充 |
| **大盘与行业参照** | 市场基准、行业指数或 ETF 的历史行情；可得历史行业归属 | 相对强弱、市场/行业敏感度、个股相对表现、市场状态 | **首批建议**；单只股票也有用 |
| **成本与可交易性信息** | 点差估计依据、费用及生效日期、成交量约束；做空时的历史借券供给与费率 | 净收益标签、换手成本、策略容量及可执行性 | **回测必需**；先选与数据精度相匹配的成本模型 |
| **第三方新闻及文本** | 原文、首次发布时间、供应商到达时间、更新版本、来源与公司映射 | 情绪、事件分类、关注度、信息新颖度 | **第二批**；文本/新闻策略才是必需 |
| **分析师预期与修正** | 当时的 EPS/营收预测、目标报告期、贡献分析师数、预测修订及快照时间 | 相对预期的业绩惊喜、预期上修/下修 | **第二批**；研究这些因子时必需 |
| **逐笔成交与报价** | 成交价量、时刻、场所、条件码、更正/撤销；同期 bid/ask 及数量 | 交易压力、点差、短期冲击、日内微观结构 | **日内按需**；逐笔策略通常应同时准备报价 |
| **其他扩展输入** | 期权、空头持仓、借券、内部人/机构持仓、宏观发布与行业经营指标 | 衍生品预期、拥挤、持有人行为、宏观/行业条件 | 有明确假设再取，见第 3 节 |

这里的“基础必需”同时包括能构造因子的输入和保证回测正确的数据。交易日历不是价格预测因子，但缺少它可能把休市当作零收益样本；成本也不能因为不属于 alpha 输入就省略。

## 2. 用户提到的四类数据，应当怎样取

### 2.1 OHLCV：必需，但需要保存原始口径

首批取得目标股票与参照资产的**原始日线**。成交量必须注明单位为股还是其他计量；有成交额、VWAP 和笔数就保存原始字段，没有则登记缺失。`close × volume` 只能是成交额代理，不等于真实成交额；由 `VWAP × volume` 重建也要求两个字段覆盖完全相同的成交集合。

记录行情来源和成交覆盖：单一交易所的数据、跨场所汇总数据不是相同的量价样本。Alpaca 官方文档区分 IEX 单市场 feed 和 SIP 汇总 feed；不要用 IEX 的成交量冒充全市场成交量，也不要在历史中无标记地切换 feed。[Alpaca 历史行情来源](https://docs.alpaca.markets/us/docs/historical-stock-data-1)

建议首轮以常规交易时段为决策范围，盘前/盘后单独标记；若数据源的日线包含其他时段，要按其实际定义使用或从更细数据重建，不能假定都是常规时段。交易日、提前收市和交易时段以历史日历为准，时间使用 UTC 并保留 `America/New_York` 交易日期语义。[NYSE 交易日历](https://www.nyse.com/trade/hours-calendars)

处理公司行动时，分别保留原始成交价格、收益序列和事件账本：

- 拆股同时影响单位股价和持股数量；价格、股数、成交量、每股财务指标必须使用一致基准。
- 明确收益是仅价格收益还是含分红总收益；用含分红收益序列计绩效时，不能再重复加同一笔分红。
- 回测持仓账本按公司行动处理股数、应收分红和实际到账。分红权益与可用现金的时间不能混为一谈。
- 调整价格不是当时真实成交报价。绝对价格门槛、交易股数、市值计算不能直接混用今天基准的复权价格和当年的原始股本。
- 不把所有事后复权一概判为未来泄漏：某些只依赖价格比例的指标对统一缩放不敏感，但仍须验证跨事件计算、现金流及特征口径。保留原始事件才能重建和核对。

例如 Massive 官方说明其行情调整支持拆股，不能由 `adjusted=true` 推断已经包含分红；其公司行动接口另提供拆股与分红记录及调整因子。[行情调整定义](https://massive.com/knowledge-base/article/is-massives-stock-data-adjusted-for-splits-or-dividends)、[公司行动接口说明](https://www.massive.com/blog/new-splits-and-dividends-endpoints)

### 2.2 财报：基本面因子的核心，要取三表和披露版本

不要只取供应商今天显示的 PE、ROE。原始项目和它们在历史上何时可知，决定了能否重算与验证。

| 原始项目组 | 建议保留的项目例子 | 可构造的候选因子 |
| --- | --- | --- |
| 利润与经营 | 营收、营业成本、营业利润、普通股股东净利润、基本/稀释 EPS、研发费用 | 收入/盈利增长、利润率及其变化、研发强度 |
| 资产与资本结构 | 总资产、归属股东权益、现金、有息债务、流动资产/负债、存货、应收账款 | ROA/ROE、杠杆、偿债能力、存货/应收相对收入变化 |
| 现金流与资本投入 | 经营现金流、资本支出、股票薪酬、发行/回购现金流 | 现金流质量、自由现金流、投资强度、现金流与利润背离 |
| 股本与分配 | 期末股份数、加权平均基本/稀释股数、股利、实际回购与新发行 | 股本稀释、每股指标变化、股息及股东回报指标 |

以上是研究侧字段要求，实际须建立 US-GAAP/IFRS/公司自定义项目的映射。银行、保险等行业应使用适合其报表结构的口径，不能强制套用普通工业企业比率。

典型构造示例：

- 盈利收益率：当时可见的 TTM 普通股利润 / 同口径的当时公司股权市值；多股份类别不能只用一个类别市值代表全部权益。
- 现金流质量：经营现金流与利润之差 / 合适的资产尺度；分子期间保持一致。
- 自由现金流收益率：按冻结口径计算的自由现金流 / 股权市值；资本支出若源数据用现金流出负号，先规范符号再计算。
- 增长变化：可比季度营收同比及其变化；历史季度不足、不连续或业务口径改变时标记不可比。

**财报时间有两个不同含义：报告期间描述经营何时发生，公开时间决定因子何时可使用。** 假设截至 3 月 31 日的业绩在 4 月 25 日收盘后公开，在只交易常规时段的设定下，最早用于随后可交易时点，不能从 3 月 31 日开始前填。若只有披露日期而没有时刻，采用事先冻结的保守延迟，并标明其为估计。

SEC 提供 submissions 历史及 XBRL 财务接口，可用于取得原始申报与结构化项目；`frames` 按最近提交事实组织，不是可直接回放所有历史时点的财务面板。研究侧需要通过 filing/版本/披露时间恢复当时可用值。标准 XBRL 汇总接口也不能代替全部自定义项目和原文解析。[SEC 数据接口](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)

季度处理规则也要保存：现金流可能为年初至今累计数；年度值、累计值、单季值和 TTM 分开。计算单季差分或 TTM 时只能使用截至决策时刻已知、期间和修订口径兼容的数据。不能把最新年报中的重述数提前替换旧季度记录。

### 2.3 新闻：先区分公司披露和第三方报道

公司财报、业绩新闻稿、指引与重要公告，是可追溯的原始披露；财经媒体、研报摘要、社交平台是其他来源。首批保留业绩披露原文与时间，不需要先下载全部媒体新闻。

若研究文本或事件因子，至少取得：`document_id, issuer_id, published_at, vendor_received_at, updated_at, source, headline, body, version, content_hash`。研究抽取结果必须能回链原文，处理转载去重、同名实体、标题误配和更新覆盖。新闻后的价格表现属于评价标签，不得作为当时新闻分数的输入。

财报提交时间不一定是业绩首次公开时间。Sharadar 官方说明其 AR 维度以 Form 10 提交日组织，某些业绩信息可能早已通过 Form 8 披露。因此，普通日频基本面研究可以从财报披露口径起步；研究“业绩发布后的反应”还必须取得更早的实际业绩发布事件。[Sharadar 时间索引说明](https://sharadar.com/docs/fundamentals#time-indexing)

### 2.4 逐笔成交：由因子与执行精度决定，不是数据越细越好

日线动量、成长或估值因子不必依赖逐笔成交。研究日内收益、开盘反应或分钟流动性时，先判断分钟线与报价是否足够；研究成交方向、订单流、秒级变化时，再取得逐笔及必要的订单簿。

逐笔成交提供成交价量，但不自动提供当时点差、可交易报价、完整订单簿或可靠的主动方标签。研究交易压力通常需要配对报价，保留方向推断方法与误差。报价/NBBO 也不保证策略订单能按显示价格和数量成交；排队与深度研究需要相应场所数据和成交模型。

日频回测若只用日线，可采用明确且保守的点差/冲击假设来初筛；不能声称已验证限价成交或日内止损先后顺序。成本对结论敏感时，再按研究需要补更细数据。

## 3. 还可以补哪些有价值的数据

| 扩展类别 | 需要的原始历史字段 | 主要用途与边界 |
| --- | --- | --- |
| 分析师预期 | 预测值、目标财年/季度、快照时间、统计方法、分析师数、修订记录 | 才能计算“超过市场预期多少”；实际 EPS 同比增长不能冒充相对共识的 surprise；GAAP 与调整后 EPS 要匹配 |
| 空头与借券 | 空头持仓数量、统计时点、发布日期、可借数量与借券费率快照 | 空头拥挤和做空成本；没有历史可借性就不能证明策略可持续做空 |
| 期权 | 合约标识、到期日/行权价、看涨/看跌、bid/ask、成交量、OI、波动率计算口径 | 隐含波动、偏斜、期限结构、衍生品活动；使用当时可见快照与期权公司行动映射 |
| 内部人及机构披露 | Form 4、13F 等原文、持仓/交易发生日、实际公开日、修订版本 | 内部人行为与披露后的机构持仓变化；季度末持仓不能被当成当天已知或实时资金流 |
| 宏观与利率 | 利率曲线、宏观发布、实际值及历史预测、发布时间、修订版本 | 市场条件和利率敏感度；经济统计的最新修订值不能回填到首次发布日 |
| 行业经营信息 | 与公司相关的可核验经营指标、发布时间、统计口径 | 例如订单、产销、用户数；按目标公司假设获取，不默认各行业通用 |
| 历史同行与成分 | 历史行业成员、指数纳入/剔除、同行行情与财务 | 相对基本面或横截面研究；必须按当时名单，不能用今天成分回填 |

FINRA 的每日 short sale volume 和空头持仓 short interest 是不同指标，前者也有场所覆盖限制。不能把空头成交量累计成空头持仓，或将它解读为方向资金净流出。[FINRA 数据定义](https://www.finra.org/finra-data/browse-catalog/short-sale-volume)

## 4. 研究侧应保存的核心数据表

以下为建议的规范化结构，不是宣称某个供应商已经提供全部字段。所有表保留 `source, source_record_id, ingested_at, dataset_version, quality_flags`；事件/披露表另存当时可见时间及依据。原始文件单独保存，派生因子不覆盖原始记录。

| 表 | 关键字段 |
| --- | --- |
| `security_master_history` | `security_id, issuer_id, cik, ticker, share_class, exchange, currency, security_type, valid_from, valid_to, available_at`；ticker/公司/股份类别分层映射 |
| `equity_bars` | `security_id, feed, session, bar_start, bar_end, open, high, low, close, volume_shares, dollar_volume, vwap, trade_count, adjustment_basis, available_at`；可选字段可空 |
| `corporate_actions` | 事件类型、公告/生效/除权/登记/支付时间、拆股比例、原始现金金额及币种、换股和现金对价、相关证券、版本与来源 |
| `shares_history` | 股本观察时点、公开时间、类别、期末/加权平均/稀释/自由流通股数及其定义；不混用这些分母 |
| `financial_facts` | 发行人、项目、值/单位/币种、期间开始/结束、季度/累计口径、GAAP 类型、filing ID、首次披露时间、供应商可见时间、修订版本 |
| `disclosure_events` | 发行人/证券、事件类型、实际公开时间、原文链接/哈希、申报编号、已公告的未来事件日及公告版本 |
| `reference_market_data` | 大盘/行业参照标识、行情和总收益口径；行业/成员关系的有效区间及公开时间 |
| `trading_calendar_status` | 交易场所、交易日期、各时段开闭市、提前收市、股票停复牌区间、状态来源 |
| `cost_constraints_history` | 适用市场/账户条件、有效时间、费用、点差/冲击模型版本、可交易股数约束；按需关联借券历史 |

CIK 是发行人层标识，不能独自区分同一公司的不同股份类别；ticker 也不是永久证券身份。历史映射应能处理更名、代码复用和证券变更。CRSP 的永久证券标识和在市/非在市证券历史是这类研究数据库设计的参考。[CRSP 美股数据库](https://indexes.morningstar.com/research-data-products/crsp-us-stock-databases)

核心对齐条件是：在决策时点 `t`，只选 `available_at <= t` 的版本，再按语义关联对应报告期/交易区间。对有效日期和公开日期同时存在的数据，两者都要检查。今天的下载时间单独存为 `ingested_at`，不能冒充历史可见时间；历史供应商到达时间不可得时，记录重建依据和延迟假设，不伪造原始观测。

## 5. 可以从哪些平台取得

以下是截至更新日核查官方资料后的候选映射，尚未对目标证券抽样验收、询价或购买。选择时按所需历史、证券范围、可见时间和公司行动完整性验收，不只比较“多少年 K 线”。

| 来源 | 适合取得的数据 | 使用时要核验什么 |
| --- | --- | --- |
| **SEC EDGAR / data.sec.gov** | 原始财务申报、XBRL 项目、申报索引及相关公司披露；公开 JSON 接口无需 API key | 自定义项目/维度是否被汇总接口省略；版本与首次公开事件需自己关联；它不提供股票价格。[官方接口](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) |

## 6. 建议的首轮获取范围

1. **目标与频率**：先固定一只目标股票、一个市场参照和一个相关行业参照；以日频/周频研究起步。参照只提供输入与评价，不自动成为交易标的。
2. **基础历史**：争取约 8–10 年可得日线及公司行动、交易状态、历史股本；实际以证券上市和各字段可靠覆盖为准，不为凑年限补造数据。财务取原生季度/年度和披露事件，保留各自缺失掩码。
3. **首轮因子家族**：量价动量/反转、波动/流动性、相对强弱、盈利/成长/现金流、估值、业绩披露后变化。没有共识预期时不开“相对预期惊喜”因子；没有文本时不开新闻情绪因子。
4. **按证据扩展**：基础因子完成滚动样本外评估后，再针对明确假设加预期修订、新闻、空头/借券或分钟/逐笔。扩展包缺失不能倒逼删除全部更早基础样本；比较模型时使用一致的重叠评价区间。

单只股票的十年季度财报大约也只有四十次季度更新。把同一份财报前填到几千个日线或更多分钟行，不会增加独立财报信息。首轮基本面宜保持少量可解释假设；若以后要学习普遍的价值/质量选股关系，再明确扩展到包含历史退市证券的多公司样本，评估方法也随之改变。

只挑今天表现好的存续股票回看，仍有目标选择偏差；单资产策略的结论应限定于选定对象，不能自动推广为美股市场普遍规律。若扩展横截面研究，历史股票池、退市损益、行业/指数成员和多股份类别处理才需要覆盖整个候选范围。

## 7. 数据进入挖掘前的验收标准

- 已明确目标证券身份、币种、历史 ticker 与股份类别，没有因代码变化拼接到别的证券。
- 量价覆盖和时段一致；休市、停牌、无成交和数据缺失可以区分，不统一填成零收益。
- 抽查拆股、分红及可得复杂公司行动：原始价格、持股数量、现金流与收益序列能相互核对；未知退市处置不假设按最后价格顺利卖出。
- 抽查财报事件：发布前不能读到新值，修订前不能读到后续重述，季度/累计值及币种单位可解释。
- 每类因子只读取当时可见的输入；未来收益、未来财报和实际事后新闻反应保存在单独标签层。
- 财务、新闻、估计值、行业成员等字段都保留各自覆盖和可见时间依据；缺少历史版本时禁用相应因子或明确缩小有效区间。
- 日线回测使用完整当日 OHLCV 后，不能假定还能无延迟按同一收盘价成交；入场时点、成本及需要的更细路径数据与策略契约一致。
- 数据版本、原始来源、清洗规则和因子定义冻结，能够从同一快照复现输入和结果。

这些是拟定的数据验收要求，本轮尚未执行数据获取或回测。
