# 单资产历史研究数据：原始字段、因子构造与获取来源

更新：2026-09-11。适用范围：以 BTC 为首个研究资产，覆盖现货与 USDT 线性永续的因子发现、策略生成和历史回测。本轮先做数据准备方案，实盘接入后置。

**最新范围说明：用户已将当前数据需求讨论明确为美股，见 [美股历史数据需求与来源](us-stock-factor-data-requirements.md)。本篇保留此前的 BTC 数据方案；OI、资金费率和期现价差清单不直接作为美股首批要求。**

关联：[因子与策略挖掘总体方案](factor-strategy-mining-agent.md)。本文不把数据空间限定在某一条趋势规则：趋势、反转、波动、量价、持仓与拥挤等假设共享基础数据，按实际可得信息扩大研究范围。

已完成官方资料检索、部分公开归档目录查询及四个小文件的内存抽样，总计约 0.55 MB；尚未建设全量数据集或修改研究代码。本次将需求按“原始字段 → 可构建因子 → 获取优先级”重排。来源与覆盖证据在第 3–5 节，不能把目录可见当成全历史已经验收。

## 1. 先明确需要取得什么数据

**首批因子输入需要七类历史信息：价格、成交活跃度、主动买卖、持仓量、资金费率、期现/参考价偏离、多空结构。** 它们覆盖时序动量、反转、波动、量价、交易压力、杠杆与拥挤等研究方向，范围不限定在一条预设趋势策略。

这是逻辑需求清单；其中价格、活跃度和主动买卖通常共用一份完整 K 线。对 BTC 永续研究，建议实际取得：**永续与现货完整 1m K 线、标记价/指数价/溢价指数历史、结算资金费率、OI 与多空比历史**，再加回测需要的合约和成本信息。

### 1.1 三种数据用途分别定义

| 用途 | 需要的数据 | 在研究中怎样使用 |
| --- | --- | --- |
| **构建因子的历史输入** | 过去价格、成交、持仓、费率、参考价格，以及按需加入的盘口等 | 在决策时刻能知道的输入；由算子生成候选因子 |
| **回测交易与核算成本** | 可成交价格/报价、费用、实际结算资金费率、合约约束、必要的更细价格路径 | 判断策略能否交易、净收益是多少；部分字段也能构造成本因子，但必须遵守可见时间 |
| **训练与评价标签** | 在固定入场/持有/退出契约下计算的未来收益、波动、最大不利变动等 | 由历史数据生成，和特征分开保存；不能被当作当时的输入 |

同一字段可有多种用途。例如费率结算值用于当次结算记账；作为因子时，只能使用已知历史或当时发布的估计值。手续费表主要用于收益核算，不能把“补齐费用信息”算作又挖到一种方向因子。

### 1.2 首轮获取与验收安排

- **先跑通基础包 Core**：永续完整 K 线、标记价/指数价、已结算费率和回测约束；能启动价格、量能、主动买卖及风险研究。
- **同批计划获取扩展包 Derivatives**：BTC 现货、溢价指数、OI、多空结构；逐项核验后开放给因子搜索。
- **按明确假设增加第二批**：逐笔、报价/L2、清算、期权、链上及外部事件；缺少这些数据的实验不允许偷偷生成依赖它们的因子。

扩展字段不齐全时，基础包继续独立使用。每类字段保留自己的覆盖和有效掩码，不把较短的 OI 历史补成全历史，也不因为 OI 缺失删掉全部更早价格样本。

## 2. 构建因子所需的历史数据清单

### 2.1 首批七类输入：字段、因子与频率

表中因子是可以检验的构造方向，不是已证明有效的预测。第一批数据的优先级由可研究范围决定，是否保留某个因子由独立评价决定。

| 类别 | 必须取得的原始字段 | 可构建的因子例子 | 原始频率与获取要求 |
| --- | --- | --- | --- |
| **① 价格路径** | `open, high, low, close`、bar 开始/结束时间；永续和现货分开 | 多周期收益、动量、均值偏离、突破位置、ATR、实现波动、趋势效率 | **基础必取**；1m，再派生 5m/15m/1h/4h/1d |
| **② 成交活跃度** | 基础币成交量、计价币成交额、成交笔数 | 放量/缩量、成交强度、平均每笔成交额、量价背离、VWAP 偏离 | **基础必取**；与价格同一份 1m K 线，保留全部量字段 |
| **③ 主动买卖压力** | 主动买入基础币量/计价币额、对应总成交量/额；更细研究再取逐笔主动方 | 主动买入占比、买卖不平衡、窗口累计成交差、压力持续性 | **基础必取可得的 bar 汇总字段**；1m 足以做第一轮，不能恢复逐笔顺序 |
| **④ 未平仓量 OI** | OI 数量、OI 计价金额、币/张单位、单双边口径、统计区间/时刻 | OI 变化率、价格与 OI 联动、成交量相对 OI、仓位扩张/去化条件 | **首批计划，核验后使用**；原生 5m 等间隔，保留更短历史 |
| **⑤ 资金费率** | 每次已结算费率、结算时刻、间隔；研究预期变化时另取当时预测快照 | 过去费率水平/分位、变化、持续性、资金成本与价格联动 | **永续必取结算历史**；原生事件频率；预测快照不从最终费率反推 |
| **⑥ 期现及参考价偏离** | 同时可见的永续价、BTC 现货价、标记价、指数价、官方溢价指数 | 期现价差、mark/index 偏离、溢价变化与历史分位、现货与永续相对量能 | **参考价进 Core，现货/溢价同批扩展**；1m，各种价格保留独立定义 |
| **⑦ 多空结构** | 全体账户多空比、大户账户多空比、大户持仓多空比及可得分子/分母、样本定义 | 结构变化、极端分位、大户与全体账户的相对差异 | **首批计划，核验后使用**；原生统计频率，不能把账户比例当资金占比 |

以 Binance 为例，完整 K 线包含成交额、笔数和主动买入量等字段，因此只保存传统六列 OHLCV 会丢掉可用于因子研究的信息。[官方字段定义](https://github.com/binance/binance-public-data#data-information)

几点解释必须随数据字典保留：

- 主动买入指买方主动成交；每笔成交都有买卖双方，主动买卖差并不等于资金进出交易所。
- OI 上升说明未平仓合约增加，本身不能识别新增多头还是空头；“价格涨且 OI 涨”是联合特征，不是直接观察到的多头净流入。
- 美元 OI 会随价格变化，必须同时保存数量口径；反向合约还需乘数和单位换算。
- 永续没有固定到期日，期现溢价不能机械按交割期货公式年化。
- 多空比样本的账户数、持仓量、单双边定义不同，必须分列登记；缺少字段就明确缺失，不自行推断。

### 2.2 实际落地的七张原始数据表

下表为**研究侧规范化字段名**，不要求供应商使用同样命名。时间、产品身份和来源字段是所有表的公共部分：`venue, instrument_id, event_time/bar_start/bar_end, available_at, availability_basis, source_hash, quality_flags`；各表按自身事件类型选择适用时间字段。

| 表 | 要保留的数据字段 | 直接服务于哪类因子 |
| --- | --- | --- |
| `perp_bars_1m` | OHLC、`base_volume, quote_volume, trade_count, taker_buy_base_volume, taker_buy_quote_volume` | ①②③；永续作为目标产品时也是价格回测基础 |
| `spot_bars_1m` | 与永续相同的完整 K 线字段 | ①②③⑥；独立标记场所和报价币 |
| `mark_bars_1m` | `mark_open, mark_high, mark_low, mark_close` | ⑥及永续风险估值；不使用占位成交量 |
| `index_bars_1m` | `index_open, index_high, index_low, index_close` | ⑥；指数成分与方法有版本时保留 |
| `premium_bars_1m` | `premium_open, premium_high, premium_low, premium_close` | ⑥；官方定义与自算价差分开 |
| `funding_events` | `settlement_time, funding_rate, interval_hours`、结算币、可得发布时刻 | ⑤及持仓现金流；预测快照另建 `funding_forecast_snapshots` |
| `derivative_metrics` | OI 数量/金额、各类账户/持仓多空比、统计窗口、数量单位和计数规则 | ④⑦；按字段保存各自有效性 |

底层保持分表，在生成某个研究快照时才按“当时可见”对齐。不得为了得到一张无空值大宽表，前填所有事件字段、跨缺口插值或删掉不完整年份。

### 2.3 从原始字段到因子的几个完整例子

以下 `t` 均表示数据已到达的决策时刻，窗口只包含当时可见历史。`C` 为同一产品收盘价，`V` 为基础币成交量；窗口长度、价格定义和费用契约随实验冻结。

| 因子例子 | 构造方式 | 所需数据及边界 |
| --- | --- | --- |
| 时序动量 | `log(C_t / C_(t-k))` | ①；不能混合现货/永续价格，不自动证明趋势持续 |
| 相对量能 | `V_t / mean(V_(t-k) … V_(t-1))` | ②；分母不含当前值，零/缺失则无效 |
| 主动买卖不平衡 | `2 × taker_buy_base_volume_t / V_t - 1` | ③；同单位、同一统计区间；V 为零则无效 |
| 窗口成交差 | 窗口内累计 `2 × taker_buy_base_volume - base_volume` | ②③；这是 bar 汇总代理，不能恢复逐笔 CVD 路径 |
| OI 变化 | `OI_qty_t / OI_qty_(t-k) - 1`，再与同期收益作交互 | ①④；OI 数量口径固定，只在有真实观测的区间计算 |
| 过去费率累积 | 决策前已发布/结算且位于过去 24h 的费率之和 | ⑤；同时保留事件数量与覆盖完整性；不等于任意持仓的实际收益 |
| 期现溢价 | `perp_price_t / spot_price_t - 1` | ⑥；统一报价币，对齐须有过期容忍度；慢一拍的价格不能当同步价格 |
| 结构差异 | 对定义明确的账户比率计算历史变化/分位，或大户与全体比率之差 | ⑦；确认正值和相同统计尺度，不能解释成直接资金流 |

参数标准化、分位阈值与因子方向在训练边界内估计；方向、状态、风险和成本因子分别评价。ATR/RSI/均线等属于由上述字段派生的特征，无需把供应商的预计算指标当成必需原始数据。

### 2.4 第二批输入：由具体研究方向决定

| 研究方向 | 新增原始数据 | 可以研究的因子 | 缺少时能否用 1m K 线代替 |
| --- | --- | --- | --- |
| **短时订单流** | 逐笔/聚合成交的 ID、时间、价、量、主动方、聚合规则 | 成交规模分布、买卖簇、冲击后的持续/回归 | 只能研究 bar 汇总代理，不能恢复逐笔规模和到达顺序 |
| **流动性与盘口** | best bid/ask 和数量；L2 初始快照、增量、序号及接收时间 | 点差、深度不平衡、微价格、价格层面的净流量 | 不能；若研究订单级撤单/排队，还要相应订单级数据 |
| **清算冲击** | 清算方向、价格、数量、事件/接收时刻、抽样规则 | 清算强度、多空清算不平衡、清算后的收益条件 | 不能由大阴线反推完整清算量 |
| **期权定价** | 历史期权链、到期/行权价、bid/ask、IV、基础价格、模型口径 | ATM IV、同到期偏斜、期限结构、隐含与实现波动差 | 不能；一个 DVOL 指数也不能恢复整条期权链 |
| **链上资金与持币结构** | 交易所净流、供给/实现市值、活跃度等，地址标签和 PiT/修订信息 | 交易所流量、持币状态、估值/供给条件 | 不能；优先小时/日频且历史可见性明确的数据 |
| **外部环境** | ETF 净流、宏观发布及修订、公告/新闻首次发布时间与文本 | 资金流、宏观状态、事件条件 | 不能；发布时间之前不得使用当日最终值 |

这不是永久推迟上述数据。如果首个研究目标改为秒级微结构，逐笔与盘口就成为该实验的基础必需输入。对于当前分钟至日频的首轮研究，先完成七类输入可以控制数据工程和搜索范围。

### 2.5 因子策略回测还要补什么

| 回测必需信息 | 最小准备内容 | 历史缺失时怎样处理 |
| --- | --- | --- |
| **手续费** | maker/taker 费率、计费资产、生效区间、实际适用档位或研究假设 | 写入明确成本情景并做敏感性，不能当成历史真实费率 |
| **合约与交易约束** | 产品类型、乘数、结算币、数量/价格步长、最小下单额；涉及永续则补保证金/清算规则 | 当前元数据不能代表过去；版本不可恢复时限制可得结论 |
| **成交价格与成本证据** | 目标场所报价/成交、点差、订单规模相关深度、决策延迟 | 先用保守且可复现的 bar 成交/成本假设；不能从 OHLCV 证明 maker 排队成交 |
| **持仓现金流** | 实际资金结算事件；涉及借贷时增加融资费率与可借条件 | 不以固定 8h 或固定费率替代全历史，不默认现货允许做空 |
| **盘中路径** | 对止损、限价等敏感分支补更细成交/价格路径 | 即使 1m 内也可能存在先后歧义，应采用一致保守规则并说明范围 |

因子表达式只能读取其声明且当时可见的数据；回测器可以读取之后发生的事件来执行与记账，不能把这些未来事件提前返回给因子。原始特征、研究标签和完整成交回放输入分别管理。

### 2.6 历史覆盖和粒度要求

- **覆盖目标**：Core 先盘点 2020 年以来到最近完整月的历史，尽量包含上涨、下跌、震荡和高波动阶段；最终由完整性与时间语义决定区间，不将年份数量当成统计充分性的保证。
- **多周期**：基础行情保存 1m；特征可以在 5m/15m/1h/4h/1d 上构造。聚合前固定 UTC 区间和闭合规则，不能因为研究 4h 就只存 4h 价格。
- **混合频率**：OI/多空比保留原生统计间隔，费率保留事件，链上/宏观保留发布频率；按可见时刻对齐并携带数据年龄，不凭空补成独立分钟样本。
- **样本一致性**：比较新增 OI 因子时，在相同有效区间上重跑无 OI 基线，同时保留基线全历史报告，避免把区间变化误当成因子增益。
- **每字段的说明**：记录来源、原名/规范化名、单位、频率、区间含义、可见规则、缺失/修订政策、可用起止和关联因子类别。交易所 OI 和多空比等公开接口的具体定义以当前官方文档逐项核验。[衍生品字段说明](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)

### 3.2 OKX：官方批量数据较完整，适合作第二场所

[官方历史数据页](https://www.okx.com/zh-hans/historical-data) 当前列出的产品级范围为：历史成交从 **2021-09**、K 线从 **2023-07**、资金费率从 **2022-03**、L2 从 **2023-03**、借币利率从 **2021-12**。这些不是每个 BTC 产品逐字段均连续的保证，下载前核对 `BTC-USDT`、`BTC-USDT-SWAP` 等具体标的。

用途：复验同一 BTC 因子是否仅依赖单场所数据；补充成交/盘口研究。访问方式为历史下载页面及公开 REST；部分批量访问的登录要求与交付粒度在实际下载时核验。[API 文档](https://www.okx.com/docs-v5/en/)

合约数量可能使用“张”，必须通过合约元数据换成统一单位；不同交易日边界、未闭合 bar、倒序返回与分页方向要验证。不要用 OKX 价格直接给 Binance 策略记成交。

### 3.3 Bybit：公开成交文件与 V5 历史接口

本轮打开 [BTCUSDT 公开成交目录](https://public.bybit.com/trading/BTCUSDT/)，看到首个列出的文件为 **2020-03-25**；这是目录观察，未检查全量文件。

[V5 Funding History](https://bybit-exchange.github.io/docs/v5/market/history-fund-rate) 提供结算费率历史，分页时应按其时间参数规则请求；[V5 Open Interest](https://bybit-exchange.github.io/docs/v5/market/open-interest) 提供 OI 时间序列与 cursor 分页，具体可取起点需按 symbol 实测。

当前 OI 文档区分双边总量 `openInterest` 和单边量 `singleOpenInterest`，并区分线性产品的 BTC 单位与反向产品的 USD 单位。不能与其他供应商的 OI 金额/单边口径直接相加。该定义可能随接口版本变化，采集时保存文档/schema 版本。

作为第二场所，OKX 与 Bybit 先选一个即可，避免第一轮扩大数据对齐和研究自由度。

### 4.1 Tardis 的历史覆盖要按字段看

官方列出 Binance USDS-M 历史入口自 **2019-11-17** 起，规范化衍生品 ticker 中 OI 自 **2020-05-13** 起；不同流的起点并不一致。每月第一天 CSV 提供免 key 样本。文档还披露早期采集问题，应读取该场所 incident/coverage 元信息，不能因为付费就跳过缺口审计。[Binance 采集详情](https://docs.tardis.dev/historical-data-details/binance-futures)

它可以提供供应商当地接收时间，这有助于评估当时可见性，但不是我们机器当时的接收时间。清算流若上游在一个时间窗只发布部分事件，供应商记录下来也不会变成完整清算总量；相关限制在上述采集文档中有说明。

### 4.2 付费前用同一个样本询价和验收

向候选供应商明确要：`Binance / BTCUSDT / USDT perpetual / 指定日期 / trades + best bid/ask + L2 + OI/funding`，分别报价，避免用“BTC 历史数据”这样无法验收的描述。

确认：每字段最早/最晚时间、原生频率、字段是否估算、交易所时间与供应商接收时间、断连/重建记录、文件修订政策、API 配额、批量交付、内部研究与生产使用授权。来源可用性和商业使用条件要以实际合同为准。

对时刻/数量定义明确的公共样本做交叉检查。若目标只是 1h/4h 的价格量能因子，先完成免费 Core；只有新的研究假设确实依赖细粒度数据，再承担长期下载与存储成本。

## 6. 数据时间和单位必须先统一

### 6.1 一个资产仍然需要精确产品身份

至少保存：`venue / native_symbol / instrument_id / product_type / base / quote / settle / multiplier / quantity_unit`。

- `BTCUSDT spot`、`BTCUSDT USDT perpetual`、`BTCUSD inverse` 是不同产品。
- USD 与 USDT、币数量与张数、基础币 OI 与美元 OI、单双边 OI 都不能直接互换。
- index/mark/premium 价格与交易价格分别建表；成交量只取有真实成交语义的字段。
- 多场所辅助特征使用各自数据到达时间，不能用事后跨场所均价替换原始价格。

### 6.2 时间字段最少保留这些

| 字段 | 含义 |
| --- | --- |
| `event_time` / `bar_start` / `bar_end` | 交易发生或统计区间；同时记录原始时间单位 |
| `published_at` | 该版本发布的时间，未知就空缺 |
| `vendor_received_at` | 供应商采集时间，来源提供时保留 |
| `ingested_at` | 我们下载/读取文件的时间；不能充当过去收到数据的时间 |
| `available_at` + `availability_basis` | 此次研究允许使用的最早时刻，明确实测/来源声明/假设 |
| `source_hash` / `revision_id` | 原始版本与修订身份 |

约束：`available_at <= decision_time`。只有归档、没有历史接收日志时，对可见性采用明确时延假设并做敏感性分析，不能声称拥有完全还原的历史信息集。

具体容易出错的地方：

1. **K 线**：4 小时 bar 的完整高低收必须在结束后使用。时间戳标开盘还是收盘，要按每个接口确认。
2. **资金费率**：结算结果用于现金流；若作入场特征，只能用当时已结算或当时已发布的估计版本。最终结算值不能回填成全天已知预测。
3. **OI**：验证时间戳是统计区间起点、终点还是发布时点；原生 5m 序列只可按明确有效期向后 as-of 对齐，不能线性插值制造中间观测。
4. **链上**：地址标注可能随研究更新；优先使用首次计算后不回改的 PiT 数据，仍核验发布时间。[Glassnode PiT 说明](https://docs.glassnode.com/data/point-in-time-metrics)
5. **宏观**：日历历史版本并不自动解决日内可见性。ALFRED 的 vintage 日期配合真实发布时间或保守日后规则使用，不能把当日新数值当成 UTC 00:00 已知。[FRED/ALFRED 时间语义](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)
6. **多周期聚合**：OHLC 按时间取首/末/极值，成交量和成交额求和，OI 通常取最后有效观测，资金现金流按事件累计；不能对所有列一律均值或求和。

## 7. 第一批数据具体怎样准备

### 7.1 第一轮仅建立免费研究底座

建议目标区间为 **2020 年初至最近一个完整月份**，以实际归档和质量报告为准。不是承诺所有字段自 2020 年完整，OI 扩展按自己的覆盖启动。

| 顺序 | 数据 | 交付 |
| --- | --- | --- |
| 1 | 列举 BTCUSDT 永续/现货的月包和扩展日包 | 原始 URL、文件日期、大小、校验信息、下载计划 manifest |
| 2 | 永续 1m K 线、标记价、指数价、资金费率 | Core 数据集和费用/元数据假设表 |
| 3 | 同场所现货 1m、溢价指数 | 期现辅助数据包 |
| 4 | OI/多空比 `metrics` | 独立时点/缺口报告，通过后合入 Derivatives 包 |
| 5 | 本地形成研究周期与可见性掩码 | 各周期特征输入表、独立标签表、固定时间切分 |
| 6 | 选 OKX 或 Bybit 的重叠小段 | 跨源差异报告，明确真实场所差异与采集错误 |

第一轮不需要全量多年逐笔和 L2，也不需要账户私有订单数据。基础 K 线能支持一批有意义的因子，但对盘中止损路径和限价成交的证明有限；相关候选以后按需求补细粒度证据。

### 7.2 首批验收

- 对每个文件验证校验和、解压、schema、时间单位和产品身份。
- 对每种数据分别报告起止、缺口、重复、冲突、异常值与原生采样间隔。
- 抽查日包/月包重叠、REST/归档重叠和 UTC 聚合一致性；不能重复计成交量。
- 区分真实零成交、数据缺失、未上线和统计停更；不把缺失价格或 OI 填零。
- 保留价格极端变化并核验来源，不通过删除暴跌时段改善回测。
- 检查 Core 与扩展字段的共同有效区间，显式输出可用掩码和最早可用时刻。
- 元数据当前值、不可恢复的历史费率或步长单列为假设，进入成本/约束敏感性。

首批交付到数据层即可：`DatasetManifest`、`DataDictionary`、`DataQualityReport`、`AvailabilityReport` 和只读研究快照。之后因子与策略 Agent 读取冻结快照，不能在搜索中临时更换来源或清洗规则。

### 7.3 存储与数据量

建议保存下载原件和校验信息；规范化后用按场所、产品、数据类型、日期分区的 Parquet。示意结构：

```text
data/factor_mining/
  raw/<source>/<product>/<symbol>/<data_type>/<date>/
  canonical/<venue>/<instrument>/<data_type>/<date>.parquet
  manifests/
  quality_reports/
  snapshots/<dataset_version>/
  labels/<label_version>/
```

这是目标结构，本轮未创建数据目录。1m 单序列一年约 **525,600 行**（不计闰日），现货加永续的六年 OHLCV 约 630 万行；mark/index 等另算。文件体积按实际月份样本估算，逐笔和 L2 不能沿用 K 线体积估算；先测平静期与高活跃期，再决定下载与存储预算。

## 8. 本轮结论与下一步边界

- **先取得 Binance 官方 Core，加现货和可验收的 OI/溢价扩展，足以启动价格、量能、波动、期现和拥挤方向的研究。** 因子的实际可用范围由质量与可见性报告决定。
- **第二场所选 OKX 或 Bybit**，用于因子与数据口径的外部对照。
- **有盘口/接收时间需求再评估 Tardis 或 Kaiko；想快速扩展衍生品聚合因子再评估 CoinGlass。** 链上用 Glassnode/CryptoQuant/Coin Metrics，宏观用 FRED/ALFRED，按假设逐项引入。
- 本轮未确定付费订阅，未全量下载，未运行因子搜索或策略回测。下一步首先把第一批数据的真实覆盖、质量和时间语义检查清楚，实盘问题留到后续阶段。
